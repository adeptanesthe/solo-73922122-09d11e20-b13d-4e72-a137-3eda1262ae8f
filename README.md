# 流式 CTC 解码工作台

面向语音算法工程师的本地网页工具：上传词表与声学模型逐帧概率，按束宽做 CTC
前缀束搜索，分块推进，随时确认 / 撤销字幕前缀，并查看每条候选的对数概率。
另提供**声学切点建议**：给定已推进的片段、字幕与字间切分处，精确计算每个帧边界
同时满足「左侧为前半句、边界前帧为 blank、右侧为后半句」的条件概率。

- 后端：FastAPI + NumPy（CTC 前缀束搜索与切点前向计算均为纯 Python/NumPy 实现，无需下载模型）
- 前端：单个静态页面（原生 JS，无构建步骤）
- 部署：`docker compose up` 即可访问 <http://localhost:8000>

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

### 本机运行

```bash
python3 -m pip install -r requirements.txt
python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

需要 Python 3.10+。页面会列出 `samples/` 下的内置样例，点击即可载入，无需任何模型文件。

## 使用流程

1. **加载数据**：上传两个 JSON 文件，或直接点击内置样例。
   - 词表：`["<blank>", "啊", "阿", "波", "播"]`（第 0 项为 blank，最多再加 8 个单字）
   - 帧概率：`{"frames": [[0.9, 0.06, 0.04], ...]}`，最多 2000 帧，每帧长度等于词表，
     取值 `0～1`（`0` 表示 `log 0 = -∞`）
2. **设置束宽**（1～16）与分块大小，点击「推进分块」或「连续推进」。
3. **查看候选**：表格按分数排序列出每个候选的 `log P`、概率、末字的 blank / 非 blank
   路径概率。把「查看帧」滑到当前帧之前的任意帧，可以回放当时已推进到的候选（只读）。
4. **确认前缀**：点「确认当前候选」，或在输入框中输入更短的前缀后确认。确认后只保留
   兼容候选，后续推进不会再把不兼容路径带回束中。
5. **撤销确认**：恢复「未做该次确认时」在当前帧应有的束与分数（不是简单解除文字限制），
   已推进的帧不会回退。
6. **切点建议**（面板 4）：填写已推进范围内的片段起止帧（含端点，2～64 帧）、
   2～16 个词表内单字组成的字幕，以及切分处（第几个字之后），点击「计算切点建议」。
   页面显示推荐切点、条件概率和完整的逐边界表；最高概率低于 0.8 时明确提示不宜切开。

### 切点概率的定义

对片段 `start..end`、字幕 `text`、切分处 `split`：

- `Z` = 片段内**所有**折叠为全文 `text` 的 CTC 路径总概率；
- `N(b)` = 同一片段内满足以下三条的路径总概率：帧 `b-1` 为 blank、
  `start..b-1` 折叠为 `text[:split]`、`b..end` 折叠为 `text[split:]`；
- 边界 `b` 的分数 = `N(b) / Z`，即条件概率 `P(切于 b | 片段折叠为全文)`。

因为边界前一帧必须是 blank，左右两半不会跨边界合并，`N(b)` 是 `Z` 的子集。
`Z` 与两侧因子都用 CTC 前向图精确计算（不是最优单路径、不是候选束近似）：
重复同字仍须经 blank 才能展开，`log 0 = -∞` 的路径贡献严格为零。评分前每帧
按行归一化；若某帧全零则无法归一化，会报告该帧而不臆造分布。全文不可达时报告
原因，不给出任何切点。

推荐规则：取条件概率最高者；数学上同分（含仅差浮点末位的对称情形）取最早边界；
最高概率 `< 0.8` 时仍显示数值与最佳边界，但标注「不宜切开」。片段 / 字幕 / 切分处
的输入范围在服务端校验：片段只接受**已经推进过**的帧。

### 切点建议的过期与迟到结果

- 每次计算都带着完整的输入（起止帧、字幕、切分处）和计算时的会话位置
  （已推进帧数、已确认前缀）返回并随会话状态保存。界面逐项展示这些输入。
- 更改片段、字幕、切分处会立即把已显示的旧建议标为「已过期」并列出差异项；
  继续推进帧或确认字幕变化后，服务端同样把旧建议标为过期。旧建议会保留显示，
  直到出现新的可用建议，不会被悄悄替换成一次失败的计算。
- 迟到结果：服务端在**收到请求时**（事件循环上，先于排队计算）递增请求序号。
  单线程 worker 按顺序完成，较早的请求若在新请求之后才完成，会标记
  `superseded: true`，绝不写入当前建议；前端再用「新会话代号 + 本地输入序列号 +
  输入逐项比对」三重校验丢弃过期响应。因此迟到结果不会冒充当前建议。
- 全零帧或全文不可达时，保留上一次成功建议（如已有），并在失败提示中说明原因。

## 关键语义与实现

### CTC 规则

- 空白记作第 0 类；同一文本的所有路径在**剪枝前**按 `log-sum-exp` 合并，
  因此同一字符串不会占用两个束位。
- 相同学分按文本的 Unicode 码点升序排列（`sorted(key=(-logp, text))`）。
- 连续重复字符只有在中间有 blank 时才会展开成两个字符；无 blank 的连续同字
  坍缩为一个字符。
- 每束保留 `logp_blank` / `logp_nonblank`，即末字以 blank 结束或非 blank 结束的
  路径概率质量。

### 任意分块一致性

`CTCBeamDecoder.advance` 只是对 `step` 的循环，确认限制也在 `step` 剪枝前应用，
所以「一次推进 N 帧」与「逐帧推进 N 次」得到完全相同的束与分数。测试
`test_chunked_equals_per_frame` 用随机 23 帧数据逐位比较。

### 确认与撤销

- 确认时记录当前束的副本（只含更早的确认限制）、确认帧号、确认文本及其精确 CTC
  前向概率（blank / 非 blank 拆分）。分数从不重新归一化。
- 撤销时从记录的副本出发，用记录的前缀限制重放确认之后已消费的帧，得到「若从未做过
  这次确认」在当前帧应有的束。这是撤销正确性的关键：仅移除文字过滤会留下被限制后
  剪枝丢失的候选。
- 撤销后若再次确认，会生成新的记录，历史确认列表也随之更新。

### 并发与迟到结果

- 每个会话有一个单线程 executor，所有推进 / 确认 / 撤销按提交顺序串行执行，
  读取（`GET /api/sessions/{id}`）也在会话锁内取快照，不会看到半更新状态。
  因此重算（撤销后的重放）期间仍可点击推进或再次撤销：这些请求排队在重算之后，
  作用于重算结果，重算的迟到响应不会覆盖它们。
- 每次状态变更使 `revision` 递增；响应携带该值。前端丢弃 `revision` 更小的响应
  （以及不属于当前会话的响应），并在切换会话时递增 `generation`。
- 操作失败（非法前缀、帧越界、会话过期等）返回 4xx，且**不修改**会话；
  前端保留原字幕与进度，仅显示错误信息。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| POST | `/api/sessions` | 用 JSON 创建会话（`vocab`、`beam_width`、`frames`） |
| POST | `/api/sessions/upload` | 上传词表与帧文件（multipart） |
| GET | `/api/sessions/{id}` | 读取当前状态 |
| DELETE | `/api/sessions/{id}` | 删除会话 |
| POST | `/api/advance` | `{session_id, to_frame}` 推进到帧边界 |
| POST | `/api/peek` | `{session_id, frame}` 回放已推进帧的候选 |
| POST | `/api/confirm` | `{session_id, prefix}` 延长已确认前缀 |
| POST | `/api/undo` | 撤销最近一次确认 |
| POST | `/api/cut-suggestion` | `{session_id, start_frame, end_frame, text, split}` 计算切点建议 |
| GET | `/api/samples`、`/api/samples/{name}` | 内置样例 |

`/api/cut-suggestion` 的响应为 `{result, state}`：`result` 含 `status`
（`ok` / `all_zero` / `unreachable`）、`inputs`、`best`（含 `cut_frame`、`prev_frame`、
`probability`、`log_probability`）、`boundaries`（每个合法边界一项）、`suitable`
（是否达到 0.8 阈值）、`superseded` 与 `computed_at`；`state` 是与其它接口一致的
会话快照，`cut_suggestion` / `cut_failure` 分别给出保留的建议与最近一次失败原因。
计算切点不会改变帧、束、已确认前缀或 `revision`。

状态中的 `beams[].logp_blank` / `logp_nonblank` 为 `null` 表示 `-∞`（JSON 无 `-Infinity`）。
`prefix_scores` 是确认时记录的末字 blank / 非 blank 路径概率（以及完整前缀分数
`logp` 与该前缀之前的分数 `previous_logp`），之后不再重新归一化或重算。

## 测试

```bash
python3 -m pytest -q tests            # 单元 + HTTP + 并发排序 + 切点测试（60 项）
python3 scripts/make_samples.py       # 重新生成内置样例
```

`tests/test_cuts.py` 用全路径枚举（`itertools.product`）独立验证条件概率：对 4～5 帧的
小样本逐边界比对，覆盖重复同字必须经 blank、零概率不可达、全零帧、同分取最早、
阈值判定与输入范围校验。`tests/test_api.py` 覆盖切点接口的正常、越界、过期标记、
失败保留旧建议，以及「迟到的旧请求被标为 `superseded` 且不成为当前建议」的并发场景。

可选的浏览器级冒烟测试（需要 jsdom，在服务已启动时执行）：

```bash

JSDOM_DIR=/tmp/uitest node tests/ui_smoke.mjs http://127.0.0.1:8000
```

该脚本使用 jsdom 驱动真实页面，覆盖：样例载入、分块推进、确认前缀、撤销后进度保留、
非法确认的错误提示、历史帧只读回放、连续推进到结尾、零概率样例不出现 NaN，以及
切点建议的显示、改切分处即时过期、重新计算、非法输入保留旧建议与低于阈值提示。

## 已知限制

- 会话保存在单进程内存中，重启即丢失；多副本部署需要外部存储。
- 束搜索为纯 Python 循环，2000 帧 × 束宽 16 约需 1.5 秒，期间通过单线程队列串行处理；
  未做多进程并行。
- 切点计算为 64 帧 × 16 字的最大请求约需 0.2～0.3 秒；请求在会话单线程队列中排队，
  不阻塞事件循环，但同一会话内的多个切点请求按到达顺序依次计算。
- 切点建议不写入会话的帧 / 束 / 前缀状态，仅保存在内存中，与其它会话状态一样重启即失。
- 页面只接受 UTF-8 编码的 JSON/文本文件，单文件大小受反向代理默认限制。
